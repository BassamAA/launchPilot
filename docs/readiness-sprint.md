# LaunchPilot / BreakthroughPilot Readiness Sprint

## Goal
Make BreakthroughPilot launch-ready for real customers by narrowing the product promise, tightening the happy path, and aligning product copy with what the software reliably delivers today.

## Launch definition
BreakthroughPilot is ready when an indie SaaS founder can:
1. Sign up
2. Paste a website URL
3. Get a useful marketing brief
4. Generate a 30-day distribution plan
5. Generate starter content
6. Review and publish through the queue
7. Understand exactly what the product does and does not automate

## ICP
- Indie SaaS founders
- Solo technical founders
- Micro-SaaS builders

## Core promise
Turn your SaaS URL into a 30-day content and distribution plan, with ready-to-review drafts and a simple publishing workflow.

## What v1 is
- Website-first analysis
- Brief generation
- Plan generation
- Starter content generation
- Queue / review workflow
- Manual + assisted publishing
- Limited automation where supported and reliable

## What v1 is not
- Fully autonomous omnichannel marketing
- Guaranteed customer acquisition
- Broad support for every business type
- Magic autopilot across every platform

## Priority workstreams
1. Positioning and copy alignment
2. Happy-path UX clarity
3. Queue-first execution model
4. Trust / proof / launch assets

## Immediate implementation plan
1. Rewrite homepage messaging to reduce overclaiming and tighten ICP
2. Update signup/onboarding/new-site flow copy to match the narrowed promise
3. Improve plan + queue page framing so planning and execution are clearly separated
4. Make settings/autopilot copy explicit about supported automation scope
5. Then evaluate remaining product blockers before touching secondary features
