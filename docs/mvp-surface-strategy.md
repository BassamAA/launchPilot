# BreakthroughPilot — MVP Surface Strategy

## Goal
Ship the smallest version of BreakthroughPilot that feels like a real multi-surface growth operator, not a dashboard with chat pasted on top.

## Core idea
The MVP should have:
- one operator brain
- one source of truth for business memory
- one setup surface
- one proactive messaging surface
- one deeper conversational work surface

That is enough to prove the thesis.

---

## Surfaces to ship first

### 1. Web onboarding + control panel
Purpose:
- connect the site
- confirm the brief
- manage integrations
- inspect queue
- inspect history
- edit the business source of truth

Why first:
- easiest place for structured setup
- necessary for integrations and settings
- already partially exists

Do not overinvest in dashboard complexity.
This is support infrastructure, not the main experience.

---

### 2. WhatsApp outbound messages
Purpose:
- daily suggestions
- reminders
- prompts
- weekly summaries
- approval requests

Why first:
- very high engagement
- fits the proactive operator thesis
- founders actually read it
- good for habit formation

WhatsApp should be the first proactive surface, not the whole product identity.

---

### 3. Web chat
Purpose:
- ask business questions
- ask strategic questions
- request draft changes
- explain why recommendations exist
- work through deeper sessions

Why first:
- easier than full rich messaging workflows everywhere
- can support longer context and structured UI
- pairs well with WhatsApp push

This becomes the first serious conversational workbench.

---

## Surfaces to delay

### Email as conversational surface
Use only for:
- weekly summary
- digest
- reporting

Do not make email a primary input surface first.

### Telegram / Slack / Discord
Useful later, but not needed to prove the core thesis.

### Native mobile app
Not needed initially if WhatsApp + web are strong.

---

## Canonical MVP loop

1. User signs up on web
2. User connects website / product
3. User confirms brief
4. System builds plan and draft base
5. System sends WhatsApp:
   - suggestion
   - reminder
   - draft idea
   - summary
6. User replies simply or clicks into web chat
7. Web chat handles deeper iteration and questions
8. Queue remains the execution record and review surface

---

## What the operator brain must support in MVP

### Memory
- business profile
- target audience
- positioning
- approved channels
- recent outputs
- recent performance
- founder preferences

### Recommendations
- what to post next
- which channel to prioritize
- when to remind
- what to repurpose
- what changed strategically

### Actions
- generate draft
- regenerate draft
- queue content
- explain reasoning
- summarize performance
- update plan preferences

---

## Minimum viable message types

### WhatsApp outbound
- daily suggestion
- weekly summary
- reminder after inactivity
- approval request

### WhatsApp inbound
- yes / no
- rewrite
- make it shorter
- make it more technical
- why
- queue it
- not now

### Web chat
- what do you know about my business?
- what should we do this week?
- what worked best?
- draft a post from this update
- why are you recommending LinkedIn?
- change the audience focus

---

## Product boundaries for MVP

### In scope
- founders
- one business memory model
- website analysis
- LinkedIn + X recommendations
- queue actions
- WhatsApp proactive outreach
- web chat Q&A and draft refinement

### Out of scope
- every social platform
- autonomous omnichannel posting
- team collaboration complexity
- broad CRM / sales functionality
- fancy dashboards beyond what supports control and trust

---

## Success criteria for MVP

The MVP is working if users feel:
1. it understands my business
2. it reminds me at the right moments
3. it tells me what to do next
4. I can ask it questions naturally
5. it saves me meaningful effort
6. I trust it enough to keep using it

The MVP is not validated just because content can be generated.
It is validated when the operator loop feels useful and sticky.

---

## Biggest risk

The biggest risk is building:
- a dashboard product
- a messaging product
- and a chat product

instead of one operator system with multiple surfaces.

Everything should route back to one brain and one memory model.

---

## Immediate implementation order

1. Keep simplifying current web app around setup + brief + plan + queue
2. Add web chat with business-memory responses
3. Add proactive WhatsApp messaging for daily suggestions and summaries
4. Add chat-driven queue actions
5. Add preference learning and stronger recommendations
